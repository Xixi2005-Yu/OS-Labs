#### 1. default_init(void)

**初始化空闲内存管理器**

```c
static void default_init(void) {
    list_init(&free_list);  // 初始化空闲页双向链表（链表头指向自身）
    nr_free = 0;            // 初始化空闲页总数为0（此时无可用物理页）
}
```

**调用时机：** pmm_init() → init_pmm_manager()中调用，是物理内存管理的初始化第一步。

**核心作用：** 搭建空闲内存管理的基础框架，用free_list串起所有空闲页块，用nr_free记录总空闲页数，为后续内存探测和分配做准备。

#### 2. default_init_memmap(struct Page *base, size_t n)

**初始化物理内存页，构建空闲页块**

```c
static void default_init_memmap(struct Page *base, size_t n) {
    assert(n > 0);
    struct Page *p = base;
    
    // 1. 初始化每个物理页的基础状态
    for (; p != base + n; p ++) {
        assert(PageReserved(p));    // 确保页初始为"内核保留"（未被使用）
        p->flags = p->property = 0; // 清空标志位和空闲块大小记录
        set_page_ref(p, 0);         // 引用计数设0（无进程使用此页）
    }
    
    // 2. 标记"空闲块首页"：记录块大小，设置"空闲块"标志
    base->property = n;             // 首页的property字段记录整个空闲块的页数（n页）
    SetPageProperty(base);          // 置位PG_property，标记此页是空闲块的首页
    
    // 3. 加入空闲链表，更新空闲页总数
    nr_free += n;
    if (list_empty(&free_list)) {
        list_add(&free_list, &(base->page_link)); // 链表空时直接添加
    } else {
        // 按物理地址升序插入（遍历链表找第一个比base大的页，插在前面）
        list_entry_t* le = &free_list;
        while ((le = list_next(le)) != &free_list) {
            struct Page* page = le2page(le, page_link);
            if (base < page) {      // 地址比较：确保链表按地址从小到大排序
                list_add_before(le, &(base->page_link));
                break;
            } else if (list_next(le) == &free_list) { // 遍历到链表尾，直接追加
                list_add(le, &(base->page_link));
            }
        }
    }
}
```

**调用时机：** kern_init() → pmm_init() → page_init() → init_memmap()，是物理内存探测后的关键步骤。

**核心作用：** 将探测到的可用物理内存（如QEMU中的0x80000000~0x88000000）转化为软件可管理的空闲页块：
- 给每个物理页初始化flags（状态）、ref（引用计数）等字段；
- 标记空闲块的"首页"（用property记录块大小，PG_property标志标识）；
- 按物理地址升序插入free_list，保证后续分配时能按地址顺序遍历。

#### 3. default_alloc_pages(size_t n)

**执行First-Fit分配，返回空闲页首地址**

```c
static struct Page *default_alloc_pages(size_t n) {
    assert(n > 0);
    if (n > nr_free) {              // 空闲页总数不足，分配失败
        return NULL;
    }
    struct Page *page = NULL;
    list_entry_t *le = &free_list;
    
    // 1. 遍历空闲链表，找"第一个大小≥n"的空闲块（First-Fit核心逻辑）
    while ((le = list_next(le)) != &free_list) {
        struct Page *p = le2page(le, page_link); // 链表节点转Page结构体
        if (p->property >= n) {     // 找到足够大的块
            page = p;
            break;
        }
    }
    
    // 2. 若找到空闲块，处理分配逻辑
    if (page != NULL) {
        list_entry_t* prev = list_prev(&(page->page_link)); // 记录块的前驱节点
        list_del(&(page->page_link));                       // 将该块从空闲链表中移除
        
        // 2.1 若块大小>n，分割块：剩余部分重新加入空闲链表
        if (page->property > n) {
            struct Page *p = page + n;          // 剩余块的首页（跳过已分配的n页）
            p->property = page->property - n;   // 剩余块大小 = 原大小 - 分配大小
            SetPageProperty(p);                 // 标记剩余块为空闲块首页
            list_add(prev, &(p->page_link));    // 插入到原块的前驱节点后
        }
        
        // 2.2 更新空闲页总数，标记已分配页的状态
        nr_free -= n;
        ClearPageProperty(page);                // 清除"空闲块首页"标志（该页已分配）
    }
    return page;                                // 返回已分配块的首页（NULL表示分配失败）
}
```

**调用时机：** 内核需要物理页时调用。

**核心作用：** 按"First-Fit"策略分配连续物理页：
- 从free_list表头开始遍历，优先选择"第一个足够大"的空闲块；
- 若块大小超过需求，分割后将剩余部分放回空闲链表；
- 移除已分配块的空闲标记，更新空闲页总数，确保后续分配逻辑正确。

#### 4. default_free_pages(struct Page *base, size_t n)

**释放物理页，合并相邻空闲块**

```c
static void default_free_pages(struct Page *base, size_t n) {
    assert(n > 0);
    struct Page *p = base;
    
    // 1. 初始化释放页的状态（标记为未使用）
    for (; p != base + n; p ++) {
        assert(!PageReserved(p) && !PageProperty(p)); // 确保页非保留、非空闲
        p->flags = 0;                                 // 清空状态标志
        set_page_ref(p, 0);                           // 引用计数设0（无进程引用）
    }
    
    // 2. 标记释放块为空闲块首页，更新空闲页总数
    base->property = n;
    SetPageProperty(base);
    nr_free += n;
    
    // 3. 按物理地址升序插入空闲链表
    if (list_empty(&free_list)) {
        list_add(&free_list, &(base->page_link));
    } else {
        list_entry_t* le = &free_list;
        while ((le = list_next(le)) != &free_list) {
            struct Page* page = le2page(le, page_link);
            if (base < page) {
                list_add_before(le, &(base->page_link));
                break;
            } else if (list_next(le) == &free_list) {
                list_add(le, &(base->page_link));
            }
        }
    }
    
    // 4. 合并"前驱空闲块"（若释放块的前一页是空闲块首页）
    list_entry_t* le = list_prev(&(base->page_link));
    if (le != &free_list) {
        p = le2page(le, page_link);
        if (p + p->property == base) {      // 前驱块的末尾 == 释放块的开头
            p->property += base->property;  // 合并大小
            ClearPageProperty(base);        // 释放块不再是首页
            list_del(&(base->page_link));   // 从链表移除释放块
            base = p;                       // 合并后新块的首页是前驱块首页
        }
    }
    
    // 5. 合并"后继空闲块"（若释放块的后一页是空闲块首页）
    le = list_next(&(base->page_link));
    if (le != &free_list) {
        p = le2page(le, page_link);
        if (base + base->property == p) {   // 释放块的末尾 == 后继块的开头
            base->property += p->property;  // 合并大小
            ClearPageProperty(p);           // 后继块不再是首页
            list_del(&(p->page_link));      // 从链表移除后继块
        }
    }
}
```

**调用时机：** 内核释放物理页时调用（如进程退出、页表销毁）。

**核心作用：** 安全释放物理页，并合并相邻空闲块，解决外部碎片问题：
- 初始化释放页的状态（清空标志、引用计数），标记为空闲块；
- 按地址升序插入空闲链表，保证链表有序性；

**关键逻辑：** 合并前驱和后继空闲块，若释放块与前后空闲块地址连续，合并为一个大空闲块，避免小块分散导致的外部碎片。

#### 其他辅助函数

此外，代码中除了这四个核心函数，还定义了一些其他函数和结构体，这些函数和结构体主要是辅助统计、算法校验、管理器注册三类功能，作用简单清晰，具体如下：

**basic_check(void)：** 对First-Fit算法做"最小化正确性校验"，覆盖分配不重复、空闲时分配失败、释放后可重新分配等基础场景，确保算法不会出现低级错误（如页地址重复、空闲数统计错误）。

### First-Fit物理内存分配完整流程

结合以上对各函数的分析，我们可以梳理First-Fit物理内存分配完整流程如下：

#### 1. 初始化阶段

内核启动后调用pmm_init()，通过default_init()初始化空闲页双向链表free_list和空闲页总数nr_free；

随后解析DTB得到物理内存范围，调用default_init_memmap()将非内核占用的物理内存转化为空闲页块，加入free_list。

#### 2. 分配阶段

当内核需要若干连续物理页时，调用default_alloc_pages(n)（n为所需页数），遍历free_list找第一个大小≥n的空闲块；

若找到，若块大小大于n，则分割为n页（分配）和剩余页（重新加入free_list），返回分配块的首页地址，内核基于此使用物理内存。

#### 3. 释放阶段

内核释放物理页时，调用default_free_pages(base, n)（base为释放页起始页，n为页数），将释放页标记为空闲并插入free_list；

检查前后是否有空闲块，且是否与当前块相邻，若有则合并，最后更新nr_free，完成释放。

### 思考：这个First-Fit算法是否有改进空间？

结合以上真实的去梳理算法的流程，以及课堂上的讲解，不难看出First-Fit算法的核心优势是分配时遍历成本低，因为它找到第一个满足条件的块即停止，但也存在明显缺陷，下面探讨一些可能的改进方向：

#### 1. 解决外部碎片问题：按块大小排序，减少碎片积累

**问题：** First-Fit按地址顺序遍历，分配后分割的小块可能分散在链表中，长期运行会产生大量外部碎片，总空闲页足够，但无连续块满足需求。

**改进方法：** 将空闲链表按块大小升序/降序排序，而非按地址排序，这也是Best-Fit算法/Worst-Fit算法的思想。

#### 2. 提升分配效率：引入块大小索引，避免全链表遍历

**问题：** 当空闲块数量较多时，First-Fit需遍历整个链表找块，分配效率随块数量增加而下降。

**改进方法：** 建立块大小索引表，如按2的幂次分组：1页、2页、4页、8页…：
- 每个索引对应一个空闲链表，存储该大小范围的空闲块；
- 分配时直接定位到最小满足需求的索引，遍历对应链表，如分配5页，定位到8页索引的链表。

#### 3. 优化内存利用率：支持非连续页分配，适配非连续需求

**问题：** First-Fit仅支持连续物理页分配，但部分场景无需连续物理页，连续分配会浪费空闲页。

**改进方法：** 结合页表机制，支持非连续物理页分配：

分配时无需找连续块，可将多个离散的物理页通过页表映射到连续的虚拟地址；典型实现如"伙伴系统"（按2的幂次分配，支持快速合并）或"Slub算法"（两级分配：先分配页，再在页内分配小内存单元），兼顾效率与利用率。

### 实现Best-Fit连续物理内存分配算法（需要编程）

在完成练习一后，参考kern/mm/default_pmm.c对First Fit算法的实现，编程实现Best Fit页面分配算法，算法的时空复杂度不做要求，能通过测试即可。请在实验报告中简要说明你的设计实现过程，阐述代码是如何对物理内存进行分配和释放，并回答如下问题：

你的Best-Fit算法是否有进一步的改进空间？

**Ans：** First-Fit和Best-Fit算法的核心差异集中在如何选择空闲块，因此其实只有alloc_pages函数需要修改，其余函数完全可以复用，我们在这里列出我们编写的Best-Fit算法的alloc_pages函数：

```c
static struct Page *
best_fit_alloc_pages(size_t n) {
    assert(n > 0);
    if (n > nr_free) {
        return NULL;
    }
    struct Page *page = NULL;
    list_entry_t *le = &free_list;
    size_t min_size = nr_free + 1; // 初始化为比最大可能值大1的数
    
    /*LAB2 EXERCISE 2: 2312642*/
    // 下面的代码是first-fit的部分代码，请修改下面的代码改为best-fit
    // 遍历空闲链表，查找满足需求的空闲页框
    // 如果找到满足需求的页面，记录该页面以及当前找到的最小连续空闲页框数量
    while ((le = list_next(le)) != &free_list) {
        struct Page *p = le2page(le, page_link);
        // 找到大小足够且更接近需求的块
        if (p->property >= n && p->property < min_size) {
            min_size = p->property;     // 更新最小块大小
            page = p;                   // 记录当前最优块
        }
    }
    
    if (page != NULL) {
        list_entry_t* prev = list_prev(&(page->page_link));
        list_del(&(page->page_link));
        if (page->property > n) {
            struct Page *p = page + n;
            p->property = page->property - n;
            SetPageProperty(p);
            list_add(prev, &(p->page_link));
        }
        nr_free -= n;
        ClearPageProperty(page);
    }
    return page;
}
```

那么代码对物理内存进行分配和释放的流程，变化主要也就体现在选择空闲块这一步上，因此再次阐述此函数的设计思路与核心逻辑：

#### 1. 前置校验

首先检查请求的页数n是否大于总空闲页数nr_free，若大于则直接返回NULL。

定义min_size变量，用于记录当前找到的最小满足需求的块大小；定义page指针用于记录最优块。

#### 2. 遍历空闲链表，筛选最优块

遍历整个空闲链表，对每个空闲块：
- 若块大小≥ n，且块大小 < min_size（比当前记录的最优块更接近需求），则更新min_size为当前块大小，并记录当前块为page。

遍历完成后，page指向的就是大小最接近需求的块。

#### 3. 处理选中的块

若找到最优块，先将该块从空闲链表中移除，避免重复分配。

若块大小 > n（块有剩余空间），则分割块：
- 从块的第n页开始作为新的空闲块，设置其大小为原大小 - n，并标记为空闲块。

将新块插入到原块的前驱节点后，维持链表有序性。

#### 4. 更新状态并返回

总空闲页数减去已分配的n页。

清除已分配块的空闲标记，返回该块的首地址。

与First-Fit的关键区别：

- First-Fit找到第一个满足需求的块就停止遍历，而Best-Fit会遍历所有块，选择剩余空间最小的块。这种策略使Best-Fit能更好地保留大空闲块，减少外部碎片，但代价是遍历成本更高。

### 思考：这个Best-Fit算法是否有进一步的改进空间？

**Ans：** Best-Fit算法的核心思想是，在所有能满足分配请求的空闲块中，选择大小最接近请求大小的块进行分配，一定程度上解决了碎片问题，但仍存在缺陷，下面是一些可能的改进方向：

**1. 效率优化：**当前需遍历所有空闲块，分配耗时随空闲块数量增加而增长。可按块大小范围建立索引（如1-4页、5-8页），分配时直接定位对应范围，减少遍历次数。

**2. 碎片管理：**虽然比First-Fit减少碎片，但长期分配释放后仍会产生零散小块。可定期触发内存整理，主动合并相邻小空闲块，或采用伙伴系统按固定大小划分块，提升合并效率。

**3. 并行处理：**多线程环境下对全局空闲链表的操作需加锁，易引发竞争。可为每个CPU核心维护本地空闲链表，仅在本地不足时才访问全局链表，降低锁冲突。

## 扩展练习Challenge3

### 硬件的可用物理内存范围的获取方法（思考题）

如果OS无法提前知道当前硬件的可用物理内存范围，请问你有何办法让OS获取可用物理内存范围？

**Ans：** 利用BIOS/UEFI接口查询内存映射

**思路：**在PC兼容机上，BIOS（Basic Input/Output System）或UEFI（Unified Extensible Firmware Interface）在启动时会扫描硬件并构建内存映射表。OS可以调用这些固件提供的接口来获取信息，而无需自己探测。这是最可靠的方式，因为它直接来自硬件固件，避免了潜在的冲突或错误。

**具体步骤：**

- 在引导加载器阶段，使用BIOS中断调用。 例如，在x86实模式下，通过INT 15h（功能码E820h）查询内存映射：

  1. 调用前设置寄存器：AX = E820h, EBX = 0（起始续接点），ES:DI指向缓冲区。

  2. BIOS返回一个结构数组，每个结构描述一个内存区域（起始地址、长度、类型，如可用内存、保留区、ACPI表等）。

  3. 如果EBX不为0，继续调用直到遍历完所有区域。


- 对于UEFI系统， 使用EFI_BOOT_SERVICES.GetMemoryMap()函数调用，获取一个EFI_MEMORY_DESCRIPTOR数组，包含类似信息。

* Bootloader将这些信息打包传递给OS内核，内核在初始化内存管理器时使用。

### OS原理重要但实验未覆盖的知识点

**1. 用户态和内核态的保护机制：**操作系统通过页表项中的权限位以及特权级机制，实现对用户进程与内核空间的访问隔离。这是操作系统内核安全的基础。通过区分用户态与内核态，系统能防止进程非法访问内核或其他进程的内存区域。实验中仅构建了单一内核空间映射，未引入用户进程与系统调用机制，所以未涉及内存保护与权限控制逻辑。

**2. 多进程与地址空间隔离：**每个进程拥有独立的虚拟地址空间，OS通过多级页表与上下文切换机制实现进程间内存隔离。地址空间隔离保证了进程的独立性与安全性，是实现多任务操作系统的核心。本实验运行在单内核模式下，未引入用户态进程、进程控制块与上下文切换，所以没有涉及多进程地址空间管理。

**3. 反向映射：**反向映射是一种通过物理页反查所有引用它的页表项（PTE）的机制，用于建立从物理地址到虚拟地址的逆向映射关系。反向映射是虚拟内存管理中的关键机制。它使得系统在执行页回收或换页时，能够快速找到并解除所有对某个物理页的引用，从而安全释放该页。本实验仅实现了从虚拟地址到物理地址的正向映射，未涉及从物理页反查页表项的反向映射。
